# N-0055 tenant scoping sweep

Baseline tree `17920fba`. API only. Nothing written to `cip`.

## Module list before

These endpoint modules named a tenant-owned model and did not filter by `tenant_id`:

buy_plans, commercial_planner, commercial_planner_intelligence_routes, competition, cpor_exports, cpor_historical_import, cpor_payment_evidence, cst_steward, imports_product_master, lineup, mappings, pricing, roadmap, shipment_evidence.

Twenty other endpoint modules already called `where_tenant` or `tenant_id_from_user`.

## Module list after

Every route on `api_router` binds `request_tenant_id` after `get_current_user` loads the user. ORM selects of the 24 tenant-owned classes then add `tenant_id ==` that value. The fourteen modules above are mounted on that router, so their reads of those classes are filtered. Login still runs with the scope unset.

Admin `sql_viewer` execute remains caller SQL and is admin-only. Its audit row is a tenant-owned class and is filtered. Tables with no `tenant_id` column are not tenant-owned rows.

Each authenticated request logs `tenant_scope bound tenant=...`.
