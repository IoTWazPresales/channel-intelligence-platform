## Concrete defects and compatibility map

### F-C1: false v1 equivalence drops row limit and sorting

**Reproduced, high correctness priority.** `dashboard_definitions.py::_v1_mirror` (line 207 onward) checks one measure, allowed grain and supported filters, but never checks `req.sort_by`, `req.sort_dir` or `req.limit`. The pure probe builds DSI units by product, ascending units, limit 1; output is `v1_equivalent=true`, `runs_v1=true`, while its v1 mirror has no sort/limit fields. The definition retains those fields, creating two representations of different questions.

`report_exports.py:149-153` and `report_delivery.py:94-105` select the v1 call from that flag; `execute_query` is called without sort/limit. Thus a widget limited to one product can export/deliver every product instead. Do not weaken query limits or reinterpret top-N to obtain parity. Minimal direction: extend the canonical equivalence predicate or shared execution adapter to preserve the query's actual contract; retain old v1 rows unchanged. Verify a saved DSI/CST report with explicit sort+limit against its widget query, including totals, row count/truncation and ordering. Add real rolled-back endpoint proof on cip_test after the pure regression.

### F-C2: ordinary promotion loses required dashboard query context

**Partly reproduced directly, high correctness priority.** `DashboardWorkspace.tsx::promoteMut` posts only widget id. `dashboards.py:679-706` copies `w.definition_v2`; it does not merge `row.filters_json` or active click/bar filters. A template `cst_sellthrough.units_per_week` widget has no own date window. `check_definition` validates it using a nominal window and reports `needs_date_range=true`, but that flag is not used in promotion. The probe recreates the definition, extracts the saved report request, and runs `plan_request`: dates are null and the request is refused with "needs period as a breakdown or both period.from and period.to."

For measures not requiring dates, this same source path can change a dated/single-customer card into an all-time/all-customer report without a warning. That is within the caller's authorization, but misrepresents the report's meaning. Existing fixed-window tests are useful and do not cover ordinary promotion. Minimal direction: preserve or explicitly resolve required execution context through the existing definition/report writer; never silently execute a broader question. Fixed snapshot versus rolling dashboard dates is a user-visible contract to propose explicitly, not a commercial amount definition. At minimum prevent creating an unexecutable saved report and explain the missing context. Verify account starter -> promote -> saved download -> delivery with required dates/customer and an out-of-window row.

### F-C3: XLSX export treats a label as a formula

**Reproduced, security/data-integrity priority.** `services/report_export.py:14-20,59-64` passes strings unchanged to openpyxl; the in-memory workbook containing fictional `product_name="=1+1"` has Data!A2 type `f`. No external URL or active exploit was used. CSV's guard in `builder/table.ts` does not protect this server XLSX path. The generic exporter predates Unit C; Unit C now routes v2 rows through it, so it is relevant to the required export surface rather than a new chart defect. Minimal direction: make untrusted text literal in the common XLSX builder while preserving actual numeric amounts. Test formula-looking names, first-character control cases, numeric negatives, and both v1/v2 saved export entry points.

### F-C4: saved v2 download endpoint is not wired into `/reports` actions

**Observed in source; not a newly reproduced browser failure.** `ReportBuilderView.tsx` has no `definition_v2` field/dispatch. `loadSaved` at line 381 loads only mirrored v1 fields; `runMut` calls v1; `exportCurrent` at line 348 always calls `/api/v1/reports/export`. A v2-only definition has `grains=[]` and its first v2 measure as metric key (`dashboard_definitions._v1_mirror`); Run/Export are disabled or unsupported. A fixed-window v2 definition with otherwise valid mirrored grains can instead export through the legacy form without its fixed window. Saved endpoint `/reports/saved/{id}/export` is correctly implemented but unused by these buttons. S20 excludes building a v2 report editor, **not** silently degrading an existing saved report. A bounded compatibility fix can identify unsupported editing, retain the saved definition and route download/schedule actions to the saved-report API; no full editor expansion required.

### F-C5: period grain omitted by legacy report calls

**Observed source, pre-existing and already named F3 in the proposal.** `deliver_saved_report` and both export paths calling v1 omit `period_grain`, even though the report stores it. The legacy volume handler can use its default grain, so a saved monthly report may produce differently grouped delivery/download rows. Existing totals-only schedule parity does not prove grain parity. Extend the canonical call contract and verify monthly/quarterly rows, not just scalar totals. Coordinate with F-C1 rather than stacking a second adapter.

### Other bounded gaps

- **Keyboard layout control:** `V2WidgetCard.tsx:279-291` and legacy card use a span with `role=button` for dragging but no `tabIndex` or key handler; `DashboardGrid.tsx:63-64` exposes pointer drag/resize and no keyboard move/resize action. Historical fullscreen/chart Enter proof is not complete keyboard operation. Implement or prove an equivalent keyboard layout action within the existing grid architecture.
- **Large filter lists:** `filterOptions.ts` fetches at most 5,000 values per model; `FilterBar.tsx:132` says "type to search" but search is only over the fetched list. A value outside that prefix cannot be found. This was an unapproved proposal deferral (F7), not S20. Measure realistic cardinality before adding a bounded server search capability; do not imply full search in the current UI.
- **PDF quality limit:** `report_export.build_pdf_bytes` emits a one-page text/JSON export with first 40 rows and up to 180 characters per row, Latin-1 replacement. It is an existing minimal download, not proof of a complete, labelled, legible multi-measure dashboard/report PDF. Current tests check header/date/value, not layout, long names, names/units or full row fidelity. Keep it an evidence/functionality gap, not a claim of total PDF absence.
- **Scheduled scope:** the authenticated test proves manual fixed-window delivery as admin; it does not exercise the real scheduler across restricted subscriber product scopes. Parent N-0115/security review must cover background context plus cache separation; do not generalize authenticated query proof to scheduled delivery.
