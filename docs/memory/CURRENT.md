**History upload: how to upload (N-0111, for Warren).** **Upload the oldest files first.** Each newer file replaces only the figures it carries and the last upload wins; replaced figures are kept, never deleted. **Customer sell-through (Amazon, Takealot, every reporting customer):** Import Center (`/admin/imports`) → **Customer sell-through** → **Upload sell-through files** → **pick the reporting customer** (the customers with **Reports expected** switched on in CST steward → Key accounts & feed profile; there is no source to pick; Amazon is customer 299) → **tick Sales-only or Stock-only** if the file has only one of them → drop the files → **Check column layouts**. A file whose headers match one of that customer's saved layouts is mapped by itself. **Map the columns the first time** a file has headers that customer has not used before: the column-mapping step opens with the detected columns, you map each header to the standard sell-through column (the product column and units or on-hand are required), name the layout, and it is saved for the customer (listed under the customer's name with Rename and Remove; a customer can have several, for example weekly report, history file, wide-week). Then **Upload files**, and finish in CST steward. **Upload the sales files first, then the stock files.** Period-named columns (a week, a month) and unit stubs (ZAR, EA) are not part of a layout, so next week's file matches the same layout. Tick boxes above the file list: **Sales-only file** for units with no on-hand; **Stock-only file** for on-hand with no units (the two exclude each other; a stock-only file never wipes sales and a sales-only file never wipes stock); a file with week numbers and no dates needs **Year of the week numbers** (the year the file starts in; pre-filled when the file or folder name has a year) and **Year confirmed** ticked, or nothing from it loads. A file that runs from week 52 into week 1 needs no split: the year moves on at week 1. Files with a sale date per line need no tick box: a column called **Date**, Sale Date, Sales Date, Transaction Date or Date Sold is read as the sale date. **Pinnacle:** Import Center → the distributor sales & inventory source → upload → check the column mapping (a "Date" column maps to the transaction date; any other date column can be picked as Date there) → validate → apply. Lines need dates (no year step). Reloading the same invoice lines replaces their figures and keeps the old ones; lines with a new invoice number are added. Lines repeated inside one file (same distributor, customer, product, date and invoice): lines that differ in any column are summed; lines identical in every column count once and are flagged duplicate. Weeks run Monday to Sunday. **"Completed with rows not loaded (N)"** in the Import Center jobs list (Status column) means N rows of that job did not load (for Pinnacle this includes rows that loaded only the sale or only the stock). Open the job (click its ID): the box at the top of the job shows rows read / loaded / not loaded and each reason with its row count, for example "Product not matched (finish in the steward)", "Week numbers without a confirmed year (tick Year confirmed)", "Units without on-hand (tick Sales-only file)" or "Missing product code or units". Fix the reason (match the products in the steward, or tick the right box and upload the file again) and the count drops. Plain **Completed** means every row read was loaded. CST steward → **Stock gap** tab (`/admin/cst-steward?tab=stock-gap`): positions on cip were recomputed on 2026-10-16, and each load recomputes the customers it touches (**Recompute** refreshes all). A week with sales but no on-hand shows **No on-hand reported** and is not compared itself; the next report is compared across it (last on-hand + matched deliveries - all sales in between). When sales are also missing for a week in between, the next report shows **Unreported weeks** (a data gap, nothing compared) and the chain starts fresh.
